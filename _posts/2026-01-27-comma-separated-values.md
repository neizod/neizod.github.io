คนโง่ที่ขยันนี่มันสร้างความเสียหายได้ใหญ่หลวงจริงๆ

อยากสำรองข้อมูลจาก database แต่ข้อมูลต้นทางมีลูกน้ำที่ไปซ้ำกับตัวแบ่งคอลัมน์ของ csv แล้วพี่จะทำไง? ก็ไม่ต้องทำให้มันเป็น "comma"-separated values ไงหล่ะ เปลี่ยนไปใช้ pipe (\|) คั่นระหว่างคอลัมน์แทน อัจฉริยะล้ำๆไปเรยยย

แต่ข้อมูลจริงของพี่ก็มี pipe อยู่ในข้อความเหมือนกันนะ ...

แล้วไงเนี่ย กรูต้องมาเขียน regex คอย validate แต่ละคอลัมน์ คอย clean ข้อมูลหลายล้าน row ให้มันถูกต้องเองงั้นเหรอ??

คือถ้าพี่จะเสียเวลา "ศึกษา" ซักนิดนึง ก็จะเห็นว่ามาตรฐาน csv มีฟันหนู ("...") ให้ใช้ครอบข้อมูลในแต่ละคอลัมน์ ขจัดปัญหาเรื่องลูกน้ำในข้อความไปเลย ไม่ต้อง workaround มาใช้ pipe แล้ว

หรือถ้าจะให้ถูกต้องกว่านี้อีก ก็สั่ง database dump มาสิโว้ย ได้ทั้ง schema ของตาราง ได้ทั้ง type ของข้อมูล ได้ constraint ได้ pk fk ระหว่างตาราง

ไม่ใช่สำรองออกมาแค่ส่วน data เป็นไฟล์ csv ที่มองทุกอย่างเป็น varchar
